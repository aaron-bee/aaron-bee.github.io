CASE STUDY · 02

CNAPP Governance & Security Automation

Making cloud security tooling operational through better signal quality, ownership, governance, and automation.

Focus
CNAPP · Cloud Security Posture · Automation · Exception Governance

Environment
Azure · AWS · GCP · SaaS · Enterprise cloud security platforms

Role
Cloud security governance, policy tuning, investigation, reporting, automation, and remediation enablement

Challenge

Cloud security platforms can generate large volumes of findings. The real problem is determining which findings matter, who owns them, what should be remediated, and which repeatable decisions can be automated.

My Role

I evaluate findings, suppression and exception requests, ownership, remediation paths, reporting needs, and automation opportunities.

What I Did

  • Reviewed cloud findings, alert logic, suppressions, and exception requests.
  • Built and refined queries for inventory, exposure analysis, compliance validation, and investigations.
  • Used PowerShell, Azure CLI, Python, and security-platform queries for reporting and automation.
  • Helped establish remediation ownership and traceability.

Key Decisions

  • Judge findings by risk relevance, not technical correctness alone.
  • Automate repeatable decisions while keeping ambiguous risk with people.
  • Preserve justification and auditability for suppressions and accepted risk.

Outcome

The work helped create more repeatable remediation and exception processes, stronger cloud visibility, clearer risk ownership, and a more scalable way to handle security findings.

Leadership Takeaway

Automation is valuable when it removes predictable work without removing accountability or risk visibility.
